# Chapter 10. Interview
## Monitoring 핵심 질문과 답변
> 각 답변은 정의, 적용 이유, 운영 주의점 순서로 설명한다.
---
# Q1. 모니터링과 옵저버빌리티의 차이는 무엇인가?
**모범 답변**
모니터링은 알려진 실패 조건을 지표와 임계값으로 확인하는 활동이다. 옵저버빌리티는 로그·메트릭·트레이스 같은 외부 신호로 미리 정의하지 않은 내부 상태까지 추론할 수 있는 성질이다.
**꼬리질문**
쇼핑몰 결제 지연에서 알려지지 않은 원인을 어떤 순서로 좁히는가?
---
# Q2. 로그, 메트릭, 트레이스는 각각 언제 사용하는가?
**모범 답변**
메트릭으로 영향과 시점을 감지하고 로그로 개별 사건의 문맥을 확인하며 트레이스로 여러 서비스에 걸친 요청 경로와 병목을 찾는다.
**꼬리질문**
세 신호를 어떤 식별자와 속성으로 연결하는가?
---
# Q3. Log Group과 Log Stream의 차이는 무엇인가?
**모범 답변**
Log Group은 보존 기간, 권한, 암호화 같은 정책 단위이며 Log Stream은 ECS Task나 인스턴스 같은 발생 원천별 이벤트 흐름이다.
**꼬리질문**
ECS 서비스 재배포 시 Stream 수명 주기는 어떻게 변하는가?
---
# Q4. 구조화 JSON 로그가 필요한 이유는 무엇인가?
**모범 답변**
필드 기반 검색과 집계가 가능하고 서비스 간 공통 스키마로 장애 쿼리를 재사용할 수 있기 때문이다.
**꼬리질문**
민감정보 유입을 수집 전에 어떻게 막는가?
---
# Q5. Metric의 Namespace와 Dimension은 무엇인가?
**모범 답변**
Namespace는 메트릭 논리 그룹이며 Dimension은 같은 이름의 메트릭을 환경이나 서비스 같은 키·값 조합으로 나누는 식별 요소이다.
**꼬리질문**
orderId를 Dimension으로 쓰면 왜 위험한가?
---
# Q6. Average 대신 p99를 봐야 하는 경우는 언제인가?
**모범 답변**
소수의 매우 느린 요청이 고객 경험과 SLO를 훼손하지만 평균에 가려질 수 있을 때 p99 같은 꼬리 지연을 본다.
**꼬리질문**
트래픽이 적을 때 percentile을 어떻게 해석하는가?
---
# Q7. Embedded Metric Format의 장단점은 무엇인가?
**모범 답변**
JSON 로그에 메트릭 선언을 포함해 비동기 추출하고 상세 속성을 로그에 유지할 수 있지만 로그 수집 비용과 스키마 관리가 필요하다.
**꼬리질문**
PutMetricData와 비교해 실패 처리 방식은 어떻게 다른가?
---
# Q8. M out of N 알람은 무엇인가?
**모범 답변**
최근 N개 평가 구간 중 M개가 임계값을 위반할 때 ALARM으로 전환하는 방식이며 순간 변동과 지속 장애를 구분하는 데 사용한다.
**꼬리질문**
3 out of 5와 5 out of 5의 탐지 특성을 비교하라.
---
# Q9. Missing Data는 어떻게 처리해야 하는가?
**모범 답변**
트래픽 없음이 정상인지, 메트릭 발행 중단이 장애인지에 따라 missing, notBreaching, breaching, ignore 중 의미에 맞는 정책을 선택한다.
**꼬리질문**
주문 요청 수와 heartbeat 메트릭에 각각 어떤 정책을 쓰는가?
---
# Q10. Composite Alarm의 목적은 무엇인가?
**모범 답변**
여러 하위 알람을 논리식으로 결합해 고객 영향과 원인 조건을 함께 평가하고 중복 알림을 줄이는 것이다.
**꼬리질문**
배포 중 알람 억제를 어떻게 안전하게 설계하는가?
---
# Q11. 알람과 오토스케일링의 차이는 무엇인가?
**모범 답변**
알람은 상태를 평가해 사람이나 작업에 알리는 장치이고 오토스케일링은 수요에 맞춰 용량을 조절하는 제어 정책이다. 확장 성공이 고객 오류 해결을 보장하지 않는다.
**꼬리질문**
CPU가 낮은 외부 API 장애에 스케일 아웃이 왜 소용없는가?
---
# Q12. RED와 USE 방법을 설명하라.
**모범 답변**
RED는 요청률, 오류, 지연으로 서비스 경험을 보고 USE는 사용률, 포화, 오류로 자원 병목을 본다.
**꼬리질문**
DB 커넥션 풀은 어떤 USE 지표로 표현하는가?
---
# Q13. 좋은 운영 대시보드의 조건은 무엇인가?
**모범 답변**
첫 화면에서 고객 영향과 심각도를 판단하고 같은 시간축으로 원인 후보를 비교하며 소유자, 상세 로그, trace, runbook으로 이동할 수 있어야 한다.
**꼬리질문**
비즈니스 지표가 필요한 이유는 무엇인가?
---
# Q14. CloudTrail Management Event와 Data Event의 차이는 무엇인가?
**모범 답변**
Management Event는 리소스 생성과 정책 변경 같은 제어 영역 작업이고 Data Event는 S3 객체 접근이나 Lambda 호출 같은 데이터 영역 작업이다.
**꼬리질문**
Data Event를 전부 활성화할 때의 위험은 무엇인가?
---
# Q15. Event History와 Trail은 어떻게 다른가?
**모범 답변**
Event History는 최근 관리 이벤트를 빠르게 조회하는 기능이며 Trail은 이벤트를 S3나 CloudWatch Logs로 지속 전달해 장기 보관과 중앙 감사를 가능하게 한다.
**꼬리질문**
장기 감사에 Event History만 의존하면 안 되는 이유는 무엇인가?
---
# Q16. 조직 Trail과 로그 무결성은 왜 필요한가?
**모범 답변**
조직 Trail은 여러 계정과 Region의 감사를 중앙화하고 로그 검증은 digest를 이용해 전달 후 변경이나 삭제 여부를 확인하게 한다.
**꼬리질문**
공격자가 운영 계정을 장악해도 로그를 지키려면 어떻게 하는가?
---
# Q17. X-Ray의 Trace, Segment, Subsegment를 설명하라.
**모범 답변**
Trace는 요청 전체 경로이고 Segment는 한 서비스의 처리 단위이며 Subsegment는 그 안의 SQL이나 외부 HTTP 호출 같은 세부 작업이다.
**꼬리질문**
서비스 맵만으로 개별 병목을 확정할 수 있는가?
---
# Q18. 분산 추적에서 Trace ID 전파가 왜 중요한가?
**모범 답변**
호출 경계마다 같은 문맥이 전달되어야 여러 서비스의 Span이 하나의 Trace로 결합되기 때문이다.
**꼬리질문**
메시지 큐와 CompletableFuture 경계에서는 어떻게 전파하는가?
---
# Q19. Sampling은 어떻게 결정하는가?
**모범 답변**
트래픽 규모, 오류 희소성, 조사 요구, 저장 비용을 기준으로 기본 비율을 정하고 오류나 느린 요청을 더 보존하는 전략을 검토한다.
**꼬리질문**
샘플되지 않은 장애는 어떤 신호로 감지하는가?
---
# Q20. OpenTelemetry와 ADOT의 관계는 무엇인가?
**모범 답변**
OpenTelemetry는 계측과 전송의 공개 표준이며 ADOT는 AWS가 제공하는 배포판으로 Agent와 Collector를 통해 OTLP 신호를 X-Ray나 AMP 같은 백엔드로 전달한다.
**꼬리질문**
Collector 장애가 고객 요청에 영향을 주지 않게 하려면 어떻게 하는가?
---
# Q21. Spring Boot Actuator와 Micrometer의 역할은 무엇인가?
**모범 답변**
Actuator는 health와 metrics 같은 운영 endpoint와 자동 구성을 제공하고 Micrometer는 여러 모니터링 백엔드에 메트릭을 연결하는 facade이다.
**꼬리질문**
liveness에 외부 DB 검사를 넣으면 어떤 문제가 생기는가?
---
# Q22. `/actuator/prometheus`와 AMP는 어떻게 연결되는가?
**모범 답변**
endpoint는 Prometheus 형식으로 메트릭을 노출하고 안전한 네트워크의 Prometheus agent나 ADOT Collector가 이를 scrape해 Amazon Managed Service for Prometheus로 remote write한다.
**꼬리질문**
endpoint를 공개 인터넷에 노출하면 안 되는 이유는 무엇인가?
---
# Q23. CloudWatch Registry와 Prometheus를 함께 쓸 때 주의점은 무엇인가?
**모범 답변**
같은 메트릭을 두 경로로 중복 발행하지 않도록 목적을 구분하고 tag, step, histogram 설정과 비용을 각각 관리해야 한다.
**꼬리질문**
어떤 환경에서 한 경로만 선택하겠는가?
---
# Q24. Correlation ID와 Trace ID의 차이는 무엇인가?
**모범 답변**
Correlation ID는 업무나 요청을 연결하기 위해 애플리케이션이 관리하는 식별자이고 Trace ID는 분산 추적 문맥의 식별자이다. 둘을 로그에 함께 남길 수 있다.
**꼬리질문**
MDC를 정리하지 않으면 어떤 장애가 발생하는가?
---
# 면접 답변 원칙
- 서비스 이름을 나열하지 않고 해결하려는 운영 질문부터 설명한다.
- 평균과 합계 같은 Statistic의 의미를 실제 지표와 연결한다.
- 비용은 정확한 숫자 대신 수집, 저장, 조회, 시계열, 샘플링 요소로 설명한다.
- 보안 질문에서는 최소 권한, 민감정보 제외, 감사 로그 분리를 함께 언급한다.
- 장애 질문에서는 탐지, 범위 축소, 완화, 복구 검증, 재발 방지 순서를 유지한다.
