# Chapter 01. 왜 Cloud가 등장했는가
## 서버 운영 문제에서 시작된 변화

> **학습 목표**
>
> - Cloud Computing이 등장한 배경을 설명할 수 있다.
> - 물리 서버 운영의 한계를 이해한다.
> - Cloud가 비용, 속도, 확장 문제를 어떻게 해결했는지 설명할 수 있다.

---

# 서버는 원래 어떻게 운영했는가

Cloud 이전에는 회사가 직접 서버를 구매하고 IDC에 설치했다.

서비스를 하나 운영하려면 다음 일을 직접 처리해야 했다.

- 서버 구매
- 랙 장착
- 전원과 네트워크 연결
- OS 설치
- 장애 대응
- 용량 증설
- 노후 장비 교체

서버는 애플리케이션 코드만 있으면 되는 것이 아니라, 물리적인 공간과 운영 인력이 함께 필요했다.

![Cloud evolution](/assets/aws-backend/cloud-evolution.png)

---

# 물리 서버 운영의 문제

가장 큰 문제는 속도와 비용이었다.

서버가 필요해도 바로 사용할 수 없었다. 구매, 배송, 설치, 네트워크 작업까지 기다려야 했다.

또한 트래픽이 얼마나 늘어날지 모르기 때문에 보통 필요한 것보다 크게 구매했다.

이 방식에는 다음 문제가 있다.

- 초기 비용이 크다.
- 증설에 시간이 오래 걸린다.
- 사용하지 않는 서버 자원이 낭비된다.
- 장애 대응을 직접 해야 한다.
- 글로벌 서비스 확장이 어렵다.

---

# Cloud가 해결한 문제

Cloud는 서버를 구매하는 방식이 아니라 필요한 만큼 빌려 쓰는 방식이다.

AWS에서는 몇 분 안에 EC2 인스턴스를 생성할 수 있고, 사용한 시간만큼 비용을 낸다.

Cloud가 해결한 핵심 문제는 다음과 같다.

| 문제 | Cloud에서의 해결 |
|---|---|
| 서버 구매가 느림 | API와 Console로 즉시 생성 |
| 초기 비용이 큼 | 사용량 기반 과금 |
| 증설이 어려움 | 필요할 때 확장 |
| 장애 대응이 어려움 | 여러 AZ와 관리형 서비스 활용 |
| 글로벌 확장이 어려움 | Region과 Edge Location 사용 |

---

# 실무 포인트

Cloud는 서버를 없앤 것이 아니다.

서버, 네트워크, 스토리지는 여전히 존재한다. 다만 사용자가 직접 장비를 구매하고 운영하지 않을 뿐이다.

백엔드 개발자는 물리 장비 대신 AWS 리소스의 구조와 책임 범위를 이해해야 한다.

---

# 기억해야 할 내용

- Cloud는 물리 서버 운영의 느림과 낭비를 줄이기 위해 등장했다.
- Cloud의 핵심은 필요한 자원을 필요한 시점에 사용하는 것이다.
- 서버 운영 책임이 모두 사라지는 것은 아니다.
- AWS를 잘 쓰려면 리소스가 실제로 어떤 인프라 위에서 동작하는지 이해해야 한다.
